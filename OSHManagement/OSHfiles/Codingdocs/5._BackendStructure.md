## Overview

### Simplified Architecture Approach
For a system with <100 users and 60 stations, we'll use a **pragmatic, simplified approach**:
- **Keep it Simple**: Avoid over-engineering for small scale
- **Direct Entity Framework**: No repository pattern needed
- **Minimal Layers**: Controllers → Services → DbContext
- **Basic Validation**: Built-in model validation instead of FluentValidation
- **Simple Background Jobs**: Basic Hangfire tasks

### Technology Stack
- **Framework**: ASP.NET Core 8.0 with Razor Pages
- **ORM**: Entity Framework Core 8.0 (direct usage)
- **Database**: SQL Server 2019+ (New) + SQL Server 2008 (Legacy sync)
- **Background Jobs**: Hangfire (basic setup)
- **Validation**: Data Annotations + server-side validation
- **Frontend**: Server-rendered HTML with Bootstrap + jQuery for interactions

## Services

### Complete Service Layer (8 comprehensive services)
| Service | Purpose & Responsibilities |
|---------|---------|
| **OrganizationalService** | Manages organizational hierarchy (OrgCategory, Station, Department, Employee, Section, OrgMetadata). Handles legacy DB synchronization, employee lookup, organizational structure validation, and station-based access control. |
| **TeamManagementService** | Unified team management (Team, TeamMember). Handles team creation with type-specific validation rules, member assignment with role validation, section representation requirements, team composition compliance, and team status management. |
| **PolicyService** | OSH policy lifecycle (OshPolicy). Manages policy creation/updates, signature tracking, responsibility definitions, communication method documentation, contractor charter management, and policy compliance status. |
| **CommitteeService** | Complete committee operations (OshCommitteeConfig, CommitteeIssue, CommitteeRecommendation, CommitteeAction). Handles committee setup, training status, meeting management, issue tracking, recommendation development, and action item assignment with progress monitoring. |
| **RiskAssessmentService** | Risk assessment process (RiskAssessmentConfig, Hazard, RiskMitigationPlan). Manages assessment scheduling, hazard identification with automated risk calculations (severity × likelihood), priority assignment, mitigation planning, and implementation tracking. |
| **IncidentService** | Incident lifecycle management (IncidentInvestigationConfig, Incident, IncidentInvestigation, IncidentCause, ControlAction, LessonLearned). Handles incident reporting, investigation team assignment, structured cause analysis, corrective action management, and organizational learning. |
| **MediaService** | Centralized file management (MediaCollection, MediaFile, MediaAssociation, MediaAccessLog, MediaConversionJob). Provides module-agnostic file upload/download, storage abstraction, access control, version management, and background processing. |
| **ComplianceService** | Cross-module compliance aggregation. Calculates station compliance scores, generates regulatory reports, monitors overdue items, tracks action completion rates, and provides executive dashboards with drill-down capabilities. |

### Why These Services?
- **Module-Based**: Each service handles one OSHA module completely
- **Business Logic**: Services contain validation and business rules
- **Direct EF Usage**: Services call DbContext directly for simplicity
- **Manageable Size**: Each service handles related entities together

### Naming Conventions
- **Services**: `{Entity}Service` (e.g., `OrganizationalService`, `IncidentService`)
- **Controllers**: `{Name}Controller` (e.g., `ApiController`, `FileController`)
- **Razor Pages**: `{Action}.cshtml` with `{Action}Model.cs` (e.g., `Create.cshtml`, `CreateModel.cs`)
- **Page Models**: `{Page}Model` (e.g., `CreateStationModel`, `EditIncidentModel`)
- **ViewModels**: `{Purpose}ViewModel` (e.g., `DashboardViewModel`, `ComplianceReportViewModel`)
- **Input Models**: `{Form}InputModel` (e.g., `CreateStationInputModel`, `ReportIncidentInputModel`)
- **Jobs**: `{Purpose}Job` (e.g., `LegacySyncJob`, `ComplianceCheckJob`)

### Razor Pages Benefits for OSHA System
1. **Form-Focused**: Perfect for compliance forms and data entry workflows
2. **Page-Per-Feature**: Clear mapping between functionality and code location
3. **Server-Rendered**: Fast loading, good for low-bandwidth environments
4. **SEO-Friendly**: Proper URLs and server-rendered content
5. **Simple State Management**: No complex client-side state to manage
6. **Progressive Enhancement**: Can add JavaScript for better UX without breaking functionality
7. **Easier Testing**: Server-side logic is easier to unit test
8. **Better Performance**: Lower memory usage compared to Blazor Server signalR connections

### Page Organization Pattern
```csharp
// Example: /Pages/Incidents/Report.cshtml.cs
public class ReportModel : PageModel
{
    private readonly IIncidentService _incidentService;

    [BindProperty]
    public ReportIncidentInput Input { get; set; }

    public async Task<IActionResult> OnPostAsync()
    {
        if (!ModelState.IsValid)
            return Page();

        await _incidentService.CreateIncidentAsync(Input);
        return RedirectToPage("/Incidents/Index");
    }
}
```
