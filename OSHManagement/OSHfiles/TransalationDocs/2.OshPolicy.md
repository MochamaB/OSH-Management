# OSH Policy Management System Design

## Overview
The OSH Policy module manages organizational safety policies, their implementation status, communication methods, responsibilities, and contractor safety commitments for each station.

## Requirements Analysis

### **Simple Form Fields**
1. **Policy Signature Status** - Yes/No checkbox
2. **Policy Implementation Status** - Yes/No checkbox
3. **Last Review Date** - Date picker
4. **Communication Methods** - Text area description
5. **Contractor Charter Exists** - Yes/No checkbox

### **Document Uploads** (handled by Media table)
- OSH Policy document (with signatures)
- Contractor safety charter document

### **Complex Data Structures**
- **OSH Responsibilities** - Multiple categories with descriptions
  - Management responsibilities
  - Factory Supervisors responsibilities
  - Outsourced labour responsibilities
  - Contractor responsibilities
  - Others responsibilities

## Database Table Design

### **1. OSH Policies Table**
**Purpose**: Store OSH policy information and compliance status for each station
**Structure**:
- `policy_id` (Primary Key - Auto-increment)
- `station_id` (Foreign Key to stations table - Links policy to specific station)

**Basic Policy Information**:
- `has_top_management_signature` (Boolean - Whether policy is signed by top management)
- `date_signed` (Date - When the policy was signed)
- `signed_by_payroll` (Employee payroll number - Who signed the policy)

**Review Information**:
- `last_reviewed_date` (Date - When policy was last reviewed)

**Implementation Status**:
- `is_policy_implemented` (Boolean - Whether policy is being actively implemented)

**Communication Methods**:
- `communication_methods` (Text - Description of how policy is communicated to staff)

**Responsibilities** (Text/JSON format for flexibility):
- `management_responsibilities` (Text - Management OSH responsibilities)
- `supervisor_responsibilities` (Text - Factory supervisor OSH responsibilities)
- `outsourced_responsibilities` (Text - Outsourced labour OSH responsibilities)
- `contractor_responsibilities` (Text - Contractor OSH responsibilities)
- `other_responsibilities` (Text - Other personnel OSH responsibilities)

**Contractor Charter**:
- `contractor_charter_exists` (Boolean - Whether contractor safety charter exists)

**Audit Fields**:
- `created_at` (DateTime - Record creation timestamp)
- `updated_at` (DateTime - Last update timestamp)
- `created_by_payroll` (Employee payroll - Who created the record)
- `updated_by_payroll` (Employee payroll - Who last updated the record)

**Constraints**:
- Foreign Key: `station_id` references `stations(station_id)`
- Unique: One policy per station (`station_id` unique constraint)

## Data Flow

### **Create/Update Policy**
1. User selects station (if multi-station access)
2. User fills out policy form
3. System validates required fields
4. System saves to osh_policies table
5. System updates audit fields (updated_by, updated_at)

### **View Policy**
1. System retrieves policy by station_id
2. System displays form with populated data
3. System shows associated documents (from Media table)
4. System displays last updated information

### **Policy Status Dashboard**
1. System queries all stations user has access to
2. System displays policy completion status
3. System highlights missing or outdated policies
4. System shows implementation status across stations

## Business Rules

### **Data Validation**
- Station must exist and be active
- Date signed cannot be in the future
- Last reviewed date cannot be in the future
- If policy is signed, date_signed and signed_by_payroll are required
- If contractor_charter_exists is true, contractor charter document should be uploaded

### **Access Control**
- Station-level access based on user permissions
- Only authorized users can modify policies
- Audit trail maintained for all changes

### **Data Relationships**
- One policy per station (unique constraint)
- Policy linked to station via foreign key
- Signed by employee must exist in employees table
- Created/updated by employees must exist in employees table
