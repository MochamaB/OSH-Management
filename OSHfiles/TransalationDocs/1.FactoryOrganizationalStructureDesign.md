# OSHA System Organizational Structure Design

Based on the legacy database analysis, here's the recommended organizational structure for the OSHA system:

## **1. OrgCategory Table**
**Purpose**: Define organizational entity types
**Structure**:
- `org_category_id` (Primary Key)
- `category_name` (Factory, HeadOffice, Region, Subsidiary)
- `description`
- `is_active`

**Categories**:
- **Factory**: Manufacturing/production facilities
- **HeadOffice**: Corporate headquarters
- **Region**: Regional management offices
- **Subsidiary**: External entities (Majani Insurance, etc.)

## **2. Station Table (Enhanced)**
**Purpose**: Organizational units/locations within each category
**Structure**:
- `station_id` (Primary Key)
- `station_code` (Business identifier - HQ, 005, 011, 367)
- `station_name` (Full name - KAPSARA, NDUTI, GACHEGE)
- `org_category_id` (Foreign Key → OrgCategory)
- `parent_station_id` (Self-referencing for hierarchy)
- `legacy_station_mapping` (Maps to legacy Station table)
- `is_active`
- `created_at`, `updated_at`

**Examples**:
- Factory: station_code="367", station_name="KAPSARA", category="Factory"
- HeadOffice: station_code="HQ", station_name="HEAD OFFICE", category="HeadOffice"
- Region: station_code="R01", station_name="REGION 1", category="Region"

## **3. Department Table (Enhanced)**
**Purpose**: Functional departments within stations
**Structure**:
- `department_id` (Primary Key)
- `department_code` (Business identifier - 101, 102, HGD, HFC)
- `department_name` (Full name)
- `station_id` (Foreign Key → Station)
- `parent_department_id` (Self-referencing for sub-departments)
- `department_head_payroll` (Current HOD)
- `legacy_department_mapping` (Maps to legacy Department table)
- `is_active`
- `created_at`, `updated_at`

## **4. Employee Table (New Design)**
**Purpose**: Employee master with proper foreign key relationships
**Structure**:
- `employee_id` (Primary Key - new auto-increment)
- `payroll_no` (Unique business identifier)
- `roll_no` (Secondary identifier)
- `first_name`, `last_name`, `other_names`
- `email_address`
- `designation`
- `station_id` (Foreign Key → Station)
- `department_id` (Foreign Key → Department)
- `supervisor_payroll` (References another employee)
- `employment_status` (Active, Inactive, Contract)
- `employee_type` (Factory, Outsourced, Other)
- `gender` (M/F)
- `hire_date`, `contract_end_date`

**Authentication Fields**:
- `username` (Login username)
- `password_hash` (Modern bcrypt hash for new passwords)
- `legacy_password` (Encrypted legacy password for migration)
- `password_reset_required` (Boolean - Force reset on first login)

**Legacy Mapping Fields**:
- `legacy_employee_station` (Original legacy station value)
- `legacy_employee_department` (Original legacy department value)
- `legacy_employee_rollno` (Original legacy roll number)
- `legacy_sync_timestamp` (Last sync from legacy DB)

**Audit Fields**:
- `is_active`
- `created_at`, `updated_at`

**Key Improvements**:
- Proper foreign key constraints
- Normalized relationships
- Clean data types
- Audit trail fields

## **5. Org_Metadata Table**
**Purpose**: Additional organizational data specific to OSHA requirements
**Structure**:
- `metadata_id` (Primary Key)
- `station_id` (Foreign Key → Station)
- `factory_manager_payroll` (FUM from OSHA requirements)
- `total_employees_male`, `total_employees_female`
- `outsourced_employees_male`, `outsourced_employees_female`
- `other_employees_male`, `other_employees_female`
- `osh_policy_exists` (Boolean)
- `osh_policy_date_signed`
- `osh_policy_last_reviewed`
- `osh_committee_exists` (Boolean)
- `risk_assessment_frequency` (Annual/Biannual/Quarterly)
- `last_risk_assessment_date`
- `contractor_charter_exists` (Boolean)
- `emergency_contact_info` (JSON field for flexibility)
- `compliance_status` (JSON field for various compliance flags)
- `created_at`, `updated_at`

**Sections Reference Table**:
- `section_id` (Primary Key)
- `station_id` (Foreign Key → Station)
- `section_name` (Field Service, Withering, Processing, Boiler/fire wood, Security, Compound)
- `section_supervisor_payroll`
- `is_active`

## **6. Legacy Synchronization Strategy**

**Sync Mapping Tables**:
- `legacy_station_mapping`: Maps legacy station strings to new station_id
- `legacy_department_mapping`: Maps legacy department codes to new department_id
- `sync_log`: Tracks synchronization runs, errors, and conflicts

**Sync Process**:
1. **Nightly Sync**: Pull changes from legacy Employee_bkp table
2. **Conflict Resolution**: Handle data inconsistencies
3. **Data Validation**: Ensure referential integrity
4. **Delta Processing**: Only sync changed records
5. **Error Logging**: Track unmappable legacy data

**Data Flow**:
```
Legacy DB → Staging Tables → Validation → Mapping → OSHA Tables → Audit Log
```

## **Authorization & Scope Control**

**Role-Based Access Control**:
- `user_roles`: Links employees to system roles
- `station_permissions`: Controls which stations a user can access
- `department_permissions`: Controls department-level access

**Scope Control Logic**:
- **Factory Manager**: Full access to their station + departments
- **Department Head**: Access to their department only
- **Regional Manager**: Access to all stations in their region
- **HQ Staff**: System-wide access based on role

## **Key Benefits of This Structure**

**1. Data Integrity**:
- Proper foreign key constraints
- Normalized relationships
- Consistent data types

**2. Flexibility**:
- Hierarchical station structure
- Extensible metadata
- Multiple employee types

**3. Legacy Integration**:
- Maintains mapping to legacy data
- Gradual migration capability
- Data validation and cleaning

**4. OSHA Compliance**:
- All required OSHA fields captured
- Audit trails for compliance
- Flexible metadata for changing requirements

**5. Authorization**:
- Station-based access control
- Department-level permissions
- Role-based functionality

This structure provides a clean, normalized database design while maintaining compatibility with the legacy system and supporting all OSHA management requirements.
