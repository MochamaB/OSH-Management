# Hazard Identification & Risk Assessment System Design

## Overview
The Hazard Risk Assessment module leverages the unified Team Management system to manage risk assessment teams, hazard identification, risk calculations, and mitigation planning for each station with minimal complexity and maximum effectiveness.

## Requirements Analysis

### **Simple Form Fields**
1. **Assessment Frequency** - Dropdown (Annual/Biannual/Quarterly)
2. **Hazard Categories** - Dropdown (Employees/Machinery/Building/Food/Others)
3. **Risk Ratings** - Automated calculation (Severity × Likelihood)

### **Document Uploads** (handled by Media table)
- Risk assessment reports
- Qualification certificates

### **Core Data Requirements**
- **Risk Assessment Team** - Managed via unified Teams system (team_type = "Risk_Assessment")
- **Hazard Identification** - Categorized hazards with risk calculations
- **Mitigation Planning** - Action assignment and tracking

## Database Table Design

### **1. Risk Assessment Config Table**
**Purpose**: Risk assessment-specific configuration and scheduling for each team
**Structure**:
- `config_id` (Primary Key - Auto-increment)
- `team_id` (Foreign Key to teams - where team_type = "Risk_Assessment")

**Assessment Schedule**:
- `assessment_frequency` (Text - Annual/Biannual/Quarterly)
- `last_assessment_date` (Date - When last assessment was completed)
- `next_assessment_date` (Date - Calculated next assessment due date)

**Team Qualification Information**:
- `team_qualifications` (Text - Team members' qualifications and experience)

**Audit Fields**:
- `created_at` (DateTime - Record creation timestamp)
- `updated_at` (DateTime - Last update timestamp)

**Constraints**:
- Foreign Key: `team_id` references `teams(team_id)`
- Unique: One config per risk assessment team (`team_id` unique constraint)

### **2. Hazards Table**
**Purpose**: Store identified hazards with automated risk calculations
**Structure**:
- `hazard_id` (Primary Key - Auto-increment)
- `team_id` (Foreign Key to teams - Risk assessment team that identified the hazard)
- `station_id` (Foreign Key to stations)
- `section_id` (Foreign Key to sections - Where hazard exists)

**Hazard Classification**:
- `hazard_category` (Text - Employees/Machinery/Building/Food/Others)
- `hazard_description` (Text - Detailed description of the hazard)

**Risk Assessment Details**:
- `affected_description` (Text - Who or what is affected)
- `impact_description` (Text - What impact/harm occurs)
- `circumstances_description` (Text - When/how the hazard occurs)
- `existing_precautions` (Text - Current safety measures in place)

**Risk Calculation** (Automated):
- `severity_level` (Integer - 1=Minor, 2=Moderate, 3=Major)
- `likelihood_level` (Integer - 1=Low, 2=Medium, 3=High)
- `risk_rating` (Integer - Calculated: severity_level × likelihood_level = 1-9)
- `priority_level` (Text - Auto-assigned: Low(1-3), Medium(4-6), High(7-9))

**Audit Fields**:
- `created_at` (DateTime - Record creation timestamp)
- `updated_at` (DateTime - Last update timestamp)

**Constraints**:
- Foreign Key: `team_id` references `teams(team_id)`
- Foreign Key: `station_id` references `stations(station_id)`
- Foreign Key: `section_id` references `sections(section_id)`
- Check: `severity_level` IN (1,2,3)
- Check: `likelihood_level` IN (1,2,3)

### **3. Risk Mitigation Plans Table**
**Purpose**: Track mitigation actions and implementation for each hazard
**Structure**:
- `mitigation_id` (Primary Key - Auto-increment)
- `hazard_id` (Foreign Key to hazards - One-to-many relationship)

**Mitigation Details**:
- `mitigation_measures` (Text - Detailed mitigation actions to be taken)
- `implementation_period` (Text - Timeline for implementation)
- `responsible_person_payroll` (Foreign Key to employees - Who is responsible)
- `monitoring_system` (Text - How implementation will be monitored)

**Implementation Tracking**:
- `implementation_status` (Text - Pending/In Progress/Completed)
- `target_completion_date` (Date - When mitigation should be completed)
- `actual_completion_date` (Date - When mitigation was actually completed)
- `completion_notes` (Text - Notes about implementation)

**Audit Fields**:
- `created_at` (DateTime - Record creation timestamp)
- `updated_at` (DateTime - Last update timestamp)

**Constraints**:
- Foreign Key: `hazard_id` references `hazards(hazard_id)`
- Foreign Key: `responsible_person_payroll` references `employees(payroll_no)`

## Implementation Approach

### **Phase 1: Team Setup**
**Risk Assessment Team Creation** (via Team Management System):
- Station selection
- Create team with `team_type = "Risk_Assessment"`
- Set `required_member_count = 5`
- Fixed member roles: Management(1), Employee(2), Outsourced(1), Other(1)

**Assessment Configuration Form**:
- Assessment frequency dropdown
- Team qualifications text area
- Assessment date scheduling

### **Phase 2: Hazard Identification**
**Hazard Entry Form**:
- Section selection dropdown
- Hazard category dropdown
- Description text areas for:
  - Hazard description
  - Affected parties
  - Impact description
  - Circumstances
  - Existing precautions
- Risk rating dropdowns:
  - Severity level (Minor/Moderate/Major)
  - Likelihood level (Low/Medium/High)
- Automatic risk calculation and priority assignment

### **Phase 3: Mitigation Planning**
**Mitigation Management Interface**:
- Link to existing hazard
- Mitigation measures text area
- Implementation period input
- Responsible person lookup
- Monitoring system description
- Status tracking and completion dates

## Risk Calculation Logic

### **Severity Levels**
- **Minor (1)**: Off duty up to 3 days / Few minutes business disruption
- **Moderate (2)**: Off duty 3+ days / One hour business disruption
- **Major (3)**: Death/major harm / 1+ day business disruption

### **Likelihood Levels**
- **Low (1)**: Rarely occurs
- **Medium (2)**: Frequently occurs
- **High (3)**: Certain/near certain to occur

### **Risk Rating Calculation**
```
Risk Rating = Severity Level × Likelihood Level
Priority Assignment:
- Low Priority: Risk Rating 1-3
- Medium Priority: Risk Rating 4-6
- High Priority: Risk Rating 7-9
```

## Data Flow

### **Team Setup Process** (via Team Management System)
1. User selects station
2. System creates team record with `team_type = "Risk_Assessment"`
3. System creates linked risk_assessment_config record
4. User assigns 5 team members via team member management (Management(1), Employee(2), Outsourced(1), Other(1))
5. User sets assessment frequency in config
6. System calculates next assessment date

### **Hazard Assessment Process**
1. User selects team (risk assessment team)
2. User selects section and category
3. User enters hazard details with team_id reference
4. User rates severity and likelihood
5. System calculates risk rating and priority
6. User creates mitigation plan linked to hazard
7. User assigns responsible person

### **Mitigation Tracking**
1. Responsible person receives assignment
2. Progress updates tracked by status
3. Completion date and notes recorded
4. System highlights overdue items

## Business Rules

### **Team Composition** (enforced by Team Management System)
- Exactly 5 members per team (1 Mgt, 2 Employee, 1 Outsourced, 1 Other)
- All team members must be active employees
- Team status validation ensures assessment capability
- Assessment frequency determines next assessment date

### **Risk Assessment**
- Risk rating automatically calculated
- Priority automatically assigned
- All hazard fields required for assessment
- Section must exist and be active

### **Mitigation Management**
- Each hazard can have multiple mitigation plans
- Responsible person must be active employee
- Status progression: Pending → In Progress → Completed

## Success Metrics

### **Assessment Coverage**
- Percentage of stations with active teams
- Assessment completion rates by frequency
- Hazard identification by category and section

### **Risk Management**
- Average risk ratings by station/section
- Mitigation completion rates
- Time to implement high-priority mitigations

This simplified design focuses on essential risk assessment functionality while maintaining the required data structure for compliance and effective hazard management.
