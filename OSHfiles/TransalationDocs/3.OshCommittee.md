# OSH Committee Management System Design

## Overview
The OSH Committee module leverages the unified Team Management system to handle committee composition, training status, meeting schedules, inspections, issues tracking, recommendations, and action items for each station.

## Requirements Analysis

### **Simple Form Fields**
1. **Training Status** - Yes/No checkbox for committee training
2. **Meeting Schedule Status** - Yes/No checkbox for schedule existence
3. **Inspection Frequency** - Dropdown (Monthly/Quarterly/Biannual)
4. **Last Inspection Date** - Date picker

### **Document Uploads** (handled by Media table)
- Training certificates
- Meeting schedules
- Committee meeting minutes
- Inspection reports

### **Complex Data Structures**
- **Committee Team** - Managed via unified Teams system (team_type = "OSH_Committee")
- **Committee Members** - Multi-type member management via Team Members
  - Management representatives (Name/Department)
  - Factory employees (Name/Section/Education Level)
- **Section Representation** - Ensure coverage across required sections
- **Issues Management** - Issue tracking with outcomes
- **Recommendations** - Recommendation tracking with implementation status
- **Action Items** - Action assignment and completion tracking

## Database Table Design



### **1. OSH Committee Config Table**
**Purpose**: Committee-specific configuration and status data
**Structure**:
- `config_id` (Primary Key - Auto-increment)
- `team_id` (Foreign Key to teams - where team_type = "OSH_Committee")

**Training Information**:
- `is_committee_trained` (Boolean - Whether committee has been trained)
- `training_date` (Date - When training was completed)

**Meeting Information**:
- `has_meeting_schedule` (Boolean - Whether meeting schedule exists)

**Inspection Information**:
- `inspection_frequency` (Text - Monthly/Quarterly/Biannual)
- `last_inspection_date` (Date - Date of last inspection)
- `next_inspection_date` (Date - Calculated next inspection date)

**Audit Fields**:
- `created_at` (DateTime - Record creation timestamp)
- `updated_at` (DateTime - Last update timestamp)

**Constraints**:
- Foreign Key: `team_id` references `teams(team_id)`
- Unique: One config per committee team (`team_id` unique constraint)

### **2. Committee Issues Table**
**Purpose**: Track issues raised by the committee
**Structure**:
- `issue_id` (Primary Key - Auto-increment)
- `team_id` (Foreign Key to teams - where team_type = "OSH_Committee")

**Issue Information**:
- `issue_title` (Text - Brief issue description)
- `issue_description` (Text - Detailed issue description)
- `issue_category` (Text - Risk Assessment/Accident/OSH Data/Statutory)
- `raised_date` (Date - When issue was raised)
- `raised_by_member_id` (Foreign Key to team_members)

**Outcome Information**:
- `previous_outcome` (Text - Previous resolution attempt results)
- `issue_status` (Text - Open/In Progress/Resolved/Closed)
- `resolution_date` (Date - When issue was resolved)
- `resolution_notes` (Text - Details of resolution)

**Audit Fields**:
- `created_at` (DateTime - Record creation timestamp)
- `updated_at` (DateTime - Last update timestamp)

**Constraints**:
- Foreign Key: `team_id` references `teams(team_id)`
- Foreign Key: `raised_by_member_id` references `team_members(member_id)`

### **3. Committee Recommendations Table**
**Purpose**: Track committee recommendations and their implementation
**Structure**:
- `recommendation_id` (Primary Key - Auto-increment)
- `team_id` (Foreign Key to teams - where team_type = "OSH_Committee")
- `issue_id` (Foreign Key to committee_issues - Optional link to related issue)

**Recommendation Information**:
- `recommendation_description` (Text - Detailed recommendation)
- `recommendation_date` (Date - When recommendation was made)
- `recommended_by_member_id` (Foreign Key to team_members)

**Implementation Information**:
- `implementation_status` (Text - Pending/In Progress/Implemented/Rejected)
- `target_completion_date` (Date - Expected completion date)
- `actual_completion_date` (Date - Actual completion date)
- `implementation_notes` (Text - Implementation details)

**Audit Fields**:
- `created_at` (DateTime - Record creation timestamp)
- `updated_at` (DateTime - Last update timestamp)

**Constraints**:
- Foreign Key: `team_id` references `teams(team_id)`
- Foreign Key: `issue_id` references `committee_issues(issue_id)`
- Foreign Key: `recommended_by_member_id` references `team_members(member_id)`

### **4. Committee Actions Table**
**Purpose**: Track action items from committee meetings
**Structure**:
- `action_id` (Primary Key - Auto-increment)
- `team_id` (Foreign Key to teams - where team_type = "OSH_Committee")
- `recommendation_id` (Foreign Key to committee_recommendations - Optional)

**Action Information**:
- `action_description` (Text - Detailed action description)
- `assigned_to_payroll` (Foreign Key to employees - Who is responsible)
- `due_date` (Date - Action due date)

**Status Information**:
- `action_status` (Text - Pending/In Progress/Completed/Overdue)
- `completion_date` (Date - When action was completed)
- `completion_notes` (Text - Details of completion)

**Audit Fields**:
- `created_at` (DateTime - Record creation timestamp)
- `updated_at` (DateTime - Last update timestamp)

**Constraints**:
- Foreign Key: `team_id` references `teams(team_id)`
- Foreign Key: `recommendation_id` references `committee_recommendations(recommendation_id)`
- Foreign Key: `assigned_to_payroll` references `employees(payroll_no)`

## Implementation Approach

### **Phase 1: Committee Setup**

**Committee Team Creation** (via Team Management System):
- Station selection (if multi-station access)
- Create team with `team_type = "OSH_Committee"`
- Set `required_member_count = 5`
- Set `requires_section_representation = true`

**Committee Configuration Form**:
- Training status checkbox with date picker
- Meeting schedule status checkbox
- Inspection frequency dropdown
- Last inspection date picker

**Member Management Interface** (via Team Management System):
- Add/Remove member buttons using unified team member system
- Member role selection (Management/Employee/Chairman/Secretary)
- Employee lookup for member selection
- Section assignment dropdown (enforced for representation)
- Education level selection
- Voting member designation

### **Phase 2: Issue & Recommendation Tracking**
**Issue Management Form**:
- Issue title and description fields
- Category selection dropdown
- Member who raised issue lookup
- Previous outcome text area
- Status tracking dropdown

**Recommendation Management Form**:
- Link to related issue (optional)
- Recommendation description text area
- Member who made recommendation lookup
- Implementation status tracking
- Target and actual completion dates

### **Phase 3: Action Item Management**
**Action Tracking Interface**:
- Action description text area
- Employee assignment lookup
- Due date picker
- Status tracking with automatic overdue detection
- Completion notes and date capture

## Data Flow

### **Committee Creation**
1. User selects station
2. System creates team record with `team_type = "OSH_Committee"`
3. System creates linked osh_committee_config record
4. User adds members via team member management
5. System validates section coverage and member count requirements
6. User sets training and schedule status in config

### **Issue Tracking Workflow**
1. Committee team member raises issue
2. Issue logged with team_id reference and category
3. Previous outcomes documented
4. Recommendations generated from issues (linked to team_id)
5. Actions created from recommendations (linked to team_id)
6. Progress tracked through completion

### **Meeting Management**
1. Meeting schedules uploaded via Media table (linked to team_id)
2. Meeting minutes uploaded after meetings
3. Actions extracted from minutes and linked to team
4. Progress reviewed and updated through team system

## Business Rules

### **Committee Composition** (enforced by Team Management System)
- Each station must have one active committee team (team_type = "OSH_Committee")
- Minimum 5 members required (enforced by team system)
- All required sections must have representation (enforced by team system)
- Both management and factory employees required
- Education levels tracked for compliance
- Team status validation ensures committee functionality

### **Issue Management**
- Issues must be categorized for reporting
- Previous outcomes required for recurring issues
- Status progression: Open → In Progress → Resolved/Closed

### **Action Tracking**
- Actions must have assignees and due dates
- Overdue actions automatically flagged
- Completion requires notes and date

## Success Metrics

### **Committee Effectiveness**
- Percentage of stations with active committees
- Section representation coverage
- Training completion rates
- Meeting schedule compliance

### **Issue Resolution**
- Average time to resolve issues
- Recommendation implementation rates
- Action completion percentages
- Recurring issue identification

This design provides comprehensive committee management while maintaining clear relationships between members, issues, recommendations, and actions for effective OSH governance.
