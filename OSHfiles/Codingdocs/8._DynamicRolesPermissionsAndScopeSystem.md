## 1. Executive Summary

### Current State (Problematic)

- ❌ **Hardcoded Scope**: Role names hardcoded in `UserScopeService` - can't add new roles without code changes
- ❌ **Unused Permissions**: 18 permissions in database but never checked in controllers
- ❌ **Legacy Ties**: Unnecessary `LegacyRoleMapping` column and sync logic
- ❌ **No UI Management**: All role/permission configuration requires SQL
- ❌ **Mixed Logic**: Scope determined by both roles AND position (confusing)

### Target State (Dynamic)

- ✅ **Dynamic Scope**: Add `ScopeLevel` to Roles → any new role automatically gets its scope
- ✅ **Permission Enforcement**: Controllers check specific permissions via policies
- ✅ **No Legacy Code**: Clean, modern role system with no legacy ties
- ✅ **UI Management**: Admin can manage roles, permissions, and scopes from UI
- ✅ **Clear Logic**: Scope determined solely by roles (position-based as fallback only)

### What's Dynamic Now?

| Feature | Before | After |
|---------|--------|-------|
| **Create New Role** | Edit code → Deploy | Insert in DB with scope → Done |
| **Change Role Scope** | Edit code → Deploy | Update DB → Next login |
| **Assign Permissions** | Write SQL | Use UI checkboxes |
| **Scope Determination** | Hardcoded `if (role == "Admin")` | Read `Role.ScopeLevel` |

**Code Location**: `Services/UserScopeService.cs:94-142`

**Current Implementation**:
```csharp
if (roles.Any(r => r.Equals("Admin", StringComparison.OrdinalIgnoreCase) ||
```

## 4. Solution Architecture

### Dynamic Scope System

```
┌─────────────────────────────────────────────────────────────┐
│  Roles Table                                                 │
│  ├── RoleName: "Station Manager"                            │
│  ├── ScopeLevel: 2 (Station) ✅ DYNAMIC!                    │
│  └── Permissions: [Incident.*, Hazard.*]                    │
└─────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  UserScopeService.DetermineScopeLevelAsync()                │
│                                                              │
│  var scope = employee.EmployeeRoles                         │
│      .Min(r => r.Role.ScopeLevel);  // Read from DB!        │
│                                                              │
│  return scope;  // No hardcoded checks ✅                   │
└─────────────────────────────────────────────────────────────┘
```

### What's Dynamic vs Static

| Component | Dynamic? | How? |
|-----------|----------|------|
| **Role → Scope** | ✅ YES | `Role.ScopeLevel` column |
| **Role → Permissions** | ✅ YES | `RolePermissions` table |
| **Permission Enforcement** | ✅ YES | Policies from DB |
| **Scope Filtering Logic** | ⚠️ SEMI | Code per entity (Employee, Incident) |
| **ScopeLevel Values** | ⚠️ SEMI | Enum (rarely changes) |

**Result**: 90% dynamic, 10% semi-static (acceptable!)

### Step 6: Update UserScopeService (Dynamic)

**File**: `Services/UserScopeService.cs`

**Replace the entire `DetermineScopeLevelAsync` method**:

```csharp
public async Task<ScopeLevel> DetermineScopeLevelAsync(int userId)
{
    var employee = await _context.Employees
        .Include(e => e.EmployeeRoles.Where(er => er.IsActive))
            .ThenInclude(er => er.Role)
        .FirstOrDefaultAsync(e => e.EmployeeId == userId);

    if (employee == null)
    {
        _logger.LogWarning($"Employee {userId} not found during scope determination");
        return ScopeLevel.Self;
    }

    // Get all active roles
    var activeRoles = employee.EmployeeRoles
        .Where(er => er.IsActive && er.Role.IsActive)
        .Select(er => er.Role)
        .ToList();

    if (!activeRoles.Any())
    {
        _logger.LogInformation($"Employee {userId} ({employee.PayrollNo}) has no active roles, checking position-based scope");

        // Fallback: Check position-based scope
        if (await IsHODAsync(employee.PayrollNo))
        {
            _logger.LogInformation($"Employee {userId} is HOD (position-based), granting Department scope");
            return ScopeLevel.Department;
        }

        if (await IsSupervisorAsync(employee.PayrollNo))
        {
            _logger.LogInformation($"Employee {userId} is Supervisor (position-based), granting Team scope");
            return ScopeLevel.Team;
        }

        _logger.LogInformation($"Employee {userId} has no roles or position, defaulting to Self scope");
        return ScopeLevel.Self;
    }

    // Get the broadest scope (lowest enum value = broadest access)
    // Organization = 1, Station = 2, Department = 3, Team = 4, Self = 5
    var broadestScope = activeRoles.Min(r => r.ScopeLevel);

    _logger.LogDebug($"Employee {userId} ({employee.PayrollNo}) has {activeRoles.Count} active role(s), broadest scope: {broadestScope}");

    return broadestScope;
}
```

**Changes**:
- ✅ **100% Dynamic**: Reads `Role.ScopeLevel` from database
- ❌ **Removed**: All hardcoded role name checks
- ✅ **Position Fallback**: Still checks HOD/Supervisor if no roles (documented)
- ✅ **Logging**: Better visibility into scope determination

**Result**: Creating new role with any scope → works immediately!

```csharp
using Microsoft.AspNetCore.Authorization;
using Microsoft.Extensions.Options;

namespace OSHManagement.Services
{
    /// <summary>
    /// Dynamically provides authorization policies for permissions
    /// Allows using [Authorize(Policy = "Permission.Name")] without pre-registering
    /// </summary>
    public class PermissionPolicyProvider : IAuthorizationPolicyProvider
    {
        private readonly DefaultAuthorizationPolicyProvider _fallbackPolicyProvider;

        public PermissionPolicyProvider(IOptions<AuthorizationOptions> options)
        {
            _fallbackPolicyProvider = new DefaultAuthorizationPolicyProvider(options);
        }

        public Task<AuthorizationPolicy> GetDefaultPolicyAsync() =>
            _fallbackPolicyProvider.GetDefaultPolicyAsync();

        public Task<AuthorizationPolicy?> GetFallbackPolicyAsync() =>
            _fallbackPolicyProvider.GetFallbackPolicyAsync();

        public Task<AuthorizationPolicy?> GetPolicyAsync(string policyName)
        {
            // Check if it's a permission-based policy (contains a dot, e.g., "Incident.Create")
            if (policyName.Contains('.'))
            {
                var policy = new AuthorizationPolicyBuilder();
                policy.RequireClaim("Permission", policyName);
                return Task.FromResult<AuthorizationPolicy?>(policy.Build());
            }

            // Check if it's a module-based policy (starts with "Module.")
            if (policyName.StartsWith("Module."))
            {
                var moduleName = policyName.Replace("Module.", "");
                var policy = new AuthorizationPolicyBuilder();
                policy.RequireAssertion(context =>
                    context.User.Claims.Any(c =>
                        c.Type == "Permission" &&
                        c.Value.StartsWith($"{moduleName}.")));
                return Task.FromResult<AuthorizationPolicy?>(policy.Build());
            }

            // Fall back to default provider
            return _fallbackPolicyProvider.GetPolicyAsync(policyName);
        }
    }
}
```

```csharp
            if (id != model.RoleId)
                return NotFound();

            if (ModelState.IsValid)
            {
                var role = await _context.Roles
                    .Include(r => r.RolePermissions)
                    .FirstOrDefaultAsync(r => r.RoleId == id);

                if (role == null)
                    return NotFound();

                // Update role properties
                role.RoleName = model.RoleName;
                role.Description = model.Description;
                role.ScopeLevel = model.ScopeLevel;
                role.AllowCrossDepartmentAccess = model.AllowCrossDepartmentAccess;
                role.AllowCrossStationAccess = model.AllowCrossStationAccess;
                role.IsActive = model.IsActive;
                role.UpdatedAt = DateTime.UtcNow;

                // Update permissions
                _context.RolePermissions.RemoveRange(role.RolePermissions);

                if (selectedPermissions != null && selectedPermissions.Any())
                {
                    foreach (var permissionId in selectedPermissions)
                    {
                        role.RolePermissions.Add(new RolePermission
                        {
                            RoleId = id,
                            PermissionId = permissionId,
                            CreatedAt = DateTime.UtcNow
                        });
                    }
                }

                await _context.SaveChangesAsync();

                TempData["SuccessMessage"] = $"Role '{role.RoleName}' updated successfully";
                return RedirectToAction(nameof(Index));
            }

            // Reload if validation fails
            var allPermissions = await _context.Permissions
                .Where(p => p.IsActive)
                .OrderBy(p => p.Module)
                .ThenBy(p => p.Action)
                .ToListAsync();

            ViewBag.AllPermissions = allPermissions.GroupBy(p => p.Module);
            ViewBag.AssignedPermissionIds = selectedPermissions ?? new List<int>();
            ViewBag.AvailableScopes = Enum.GetValues<ScopeLevel>();

            return View(model);

            if (role == null)

            {
                TempData["ErrorMessage"] = $"Cannot delete role - {employeeCount} employee(s) still assigned";
                return RedirectToAction(nameof(Index));
            }

            _context.Roles.Remove(role);
            await _context.SaveChangesAsync();

            TempData["SuccessMessage"] = $"Role '{role.RoleName}' deleted successfully";
            return RedirectToAction(nameof(Index));
        }
```

### Step 9: Auto-Generate Permissions (Optional)

**File**: Create `Services/PermissionGeneratorService.cs`

```csharp
using Microsoft.EntityFrameworkCore;
using OSHManagement.Data;
using OSHManagement.Models;
using System.Reflection;
using Microsoft.AspNetCore.Mvc;

namespace OSHManagement.Services
{
    /// <summary>
    /// Automatically generates permissions based on controller actions
    /// </summary>
    public class PermissionGeneratorService
    {
        private readonly OshDbContext _context;
        private readonly ILogger<PermissionGeneratorService> _logger;

        public PermissionGeneratorService(OshDbContext context, ILogger<PermissionGeneratorService> logger)
        {
            _context = context;
            _logger = logger;
        }

        public async Task<int> GeneratePermissionsAsync()
        {
            _logger.LogInformation("Generating permissions from controllers...");

            var assembly = Assembly.GetExecutingAssembly();
            var controllerTypes = assembly.GetTypes()
                .Where(t => typeof(Controller).IsAssignableFrom(t) &&
                           !t.IsAbstract &&
                           t.Name.EndsWith("Controller") &&
                           t.Name != "ScopedController")
                .ToList();

            int newPermissionsCount = 0;

            foreach (var controllerType in controllerTypes)
            {
                var moduleName = controllerType.Name.Replace("Controller", "");
                var actions = GetCrudActions(controllerType);

                foreach (var action in actions)
                {
                    var permissionName = $"{moduleName}.{action}";

                    if (!await _context.Permissions.AnyAsync(p => p.PermissionName == permissionName))
                    {
                        var permission = new Permission
                        {
                            PermissionName = permissionName,
                            Description = $"{action} {moduleName}",
                            Module = moduleName,
                            Action = action,
                            IsActive = true,
                            CreatedAt = DateTime.UtcNow
                        };

                        _context.Permissions.Add(permission);
                        newPermissionsCount++;
                        _logger.LogInformation($"Created permission: {permissionName}");
                    }
                }
            }

            if (newPermissionsCount > 0)
            {
                await _context.SaveChangesAsync();
                _logger.LogInformation($"✅ Generated {newPermissionsCount} new permissions");
            }
            else
            {
                _logger.LogInformation("No new permissions needed");
            }

            return newPermissionsCount;
        }

        private HashSet<string> GetCrudActions(Type controllerType)
        {
            var actions = new HashSet<string>();
            var methods = controllerType.GetMethods(BindingFlags.Public | BindingFlags.Instance | BindingFlags.DeclaredOnly);

            foreach (var method in methods)
            {
                // Skip non-action methods
                if (method.GetCustomAttribute<NonActionAttribute>() != null)
                    continue;

                // Map standard action names to CRUD
                if (method.Name == "Index" || method.Name == "List" || method.Name == "Details")
                    actions.Add("Read");
                else if (method.Name == "Create")
                    actions.Add("Create");
                else if (method.Name == "Edit" || method.Name == "Update")
                    actions.Add("Update");
                else if (method.Name == "Delete")
                    actions.Add("Delete");
                else
                    // Custom action
                    actions.Add(method.Name);
            }

            return actions;
        }
    }
}
```

## 7. FAQs

### Q: Can I add new scope levels beyond the 5 we have?

**A**: Yes, but requires code change to ScopeLevel enum and filtering logic. Example:
```csharp
public enum ScopeLevel
{
    Organization = 1,
    Region = 2,  // NEW
    Station = 3,
    Department = 4,
    Team = 5,
    Self = 6
}
```

Then update filtering methods to handle Region scope.

### Q: What if employee has both role-based and position-based scope?

**A**: Role-based wins. Position-based (HOD/Supervisor) is only a fallback if no roles assigned.

### Q: How do I prevent deleting critical roles?

**A**: Set `IsSystemRole = true` for Admin, Employee, etc. Controller checks this before deleting.

### Q: Can roles have different permissions for same scope level?

**A**: Yes! "Safety Officer" and "Station Manager" both have Station scope but different permissions.

### Q: How often should I run auto-generate permissions?

**A**: During development after adding new controllers. In production, manually add via UI as needed.
