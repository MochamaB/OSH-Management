# Data Access Filtering (Scope-Based Authorization)

## Overview

The OSH Management System implements a **dynamic scope-based data access filtering system** that automatically restricts what data users can see based on their roles and organizational position. After the recent update to use **dynamic roles with ScopeLevel**, the system is now fully database-driven - new roles can be added without code changes.

## Scope Levels

The system defines five hierarchical scope levels (enum values), from broadest to most restrictive:

```csharp
public enum ScopeLevel
{
    Organization = 1,  // Broadest - sees ALL data
    Station = 2,       // Station-wide data
    Department = 3,    // Department-wide data
    Team = 4,          // Direct reports only
    Self = 5           // Most restrictive - own data only
}
```

### 1. Organization (`ScopeLevel.Organization = 1`)
- **Access**: All data across the entire organization
- **Example Roles**: Admin, OSH Manager, HR Manager
- **Created via**: Roles table with `ScopeLevel = 1`
- **Example**: Can see all employees, incidents, and hazards across all stations

### 2. Station (`ScopeLevel.Station = 2`)
- **Access**: All data within the user's assigned station
- **Example Roles**: Station Manager, Safety Officer
- **Created via**: Roles table with `ScopeLevel = 2`
- **Example**: Can see all employees within their station, station-level incidents

### 3. Department (`ScopeLevel.Department = 3`)
- **Access**: All data within the user's assigned department
- **Example Roles**: Department Head, Department Safety Rep
- **Created via**: Roles table with `ScopeLevel = 3`, OR position-based (HOD field)
- **Example**: Can see employees in their department, station-level incidents

### 4. Team (`ScopeLevel.Team = 4`)
- **Access**: Only direct reports (team members supervised by the user)
- **Example Roles**: Supervisor, Safety Coordinator
- **Created via**: Roles table with `ScopeLevel = 4`, OR position-based (Supervisor field)
- **Example**: Can see direct reports, incidents they reported or were affected by

### 5. Self (`ScopeLevel.Self = 5`)
- **Access**: Only the user's own data
- **Example Roles**: Employee (default), Contractor
- **Created via**: Roles table with `ScopeLevel = 5` (auto-assigned to new employees)
- **Example**: Can only see their own employee record, own incidents

## Architecture Overview

The scope system uses a **multi-layered approach** with these key components:

```
┌─────────────────────────────────────────────────────────┐
│              1. AUTHENTICATION (Login)                   │
│  - UserScopeService determines scope from Role.ScopeLevel│
│  - Scope added to authentication claims                 │
└────────────────────┬────────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────────┐
│              2. REQUEST HANDLING                         │
│  - Scope read from claims (CurrentScope)                │
│  - Available in all requests via HttpContext            │
└────────────────────┬────────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────────┐
│              3. CONTROLLER LAYER                         │
│  - ScopedController provides ApplyScope<T>() method     │
│  - Automatically filters queries based on scope         │
└────────────────────┬────────────────────────────────────┘
                     │
┌────────────────────▼────────────────────────────────────┐
│              4. SERVICE LAYER                            │
│  - ScopeFilterService routes to entity-specific filters │
│  - ApplyEmployeeScope(), ApplyIncidentScope(), etc.     │
└─────────────────────────────────────────────────────────┘
```

## How Scope Works

### During Login (Authentication)

When a user logs in, the system:

1. **Authenticates** the user (password verification)
2. **Determines scope** via `UserScopeService.DetermineScopeLevelAsync()`:
   - Loads employee's active roles from database
   - Gets `Role.ScopeLevel` for each role
   - Takes **broadest scope** (lowest ScopeLevel value = Min())
   - Falls back to position-based scope (HOD/Supervisor) if no roles
3. **Adds scope claims** to authentication cookie:
   - `Scope`: "Organization", "Department", "Self", etc.
   - `StationId`: User's station
   - `DepartmentId`: User's department
   - `PayrollNo`: User's payroll number
4. **Creates ClaimsPrincipal** with all claims

#### Dynamic Scope Determination Logic

```csharp
public async Task<ScopeLevel> DetermineScopeLevelAsync(int userId)
{
    var employee = await _context.Employees
        .Include(e => e.EmployeeRoles.Where(er => er.IsActive))
            .ThenInclude(er => er.Role)
        .FirstOrDefaultAsync(e => e.EmployeeId == userId);

    // Get all active roles
    var activeRoles = employee.EmployeeRoles
        .Where(er => er.IsActive && er.Role.IsActive)
        .Select(er => er.Role)
        .ToList();

    if (!activeRoles.Any())
    {
        // FALLBACK: Position-based scope
        if (await IsHODAsync(employee.PayrollNo))
            return ScopeLevel.Department;

        if (await IsSupervisorAsync(employee.PayrollNo))
            return ScopeLevel.Team;

        return ScopeLevel.Self;
    }

    // PRIMARY: Get broadest scope from roles
    // Organization=1, Station=2, Dept=3, Team=4, Self=5
    // Lower number = broader access
    var broadestScope = activeRoles.Min(r => r.ScopeLevel);

    return broadestScope;
}
```

**Key Points**:
- ✅ **Dynamic**: Reads `ScopeLevel` from database, not hardcoded
- ✅ **Multiple Roles**: User can have multiple roles - broadest scope wins
- ✅ **Fallback**: If no roles, checks HOD/Supervisor position fields
- ✅ **Extensible**: New roles can be added via database insert

### During Requests

On each HTTP request, the scope is **read from claims**:

```csharp
public UserScope? GetCurrentUserScope()
{
    var user = _httpContextAccessor.HttpContext?.User;

    var scopeClaim = user.FindFirst("Scope")?.Value;
    var stationIdClaim = user.FindFirst("StationId")?.Value;
    var departmentIdClaim = user.FindFirst("DepartmentId")?.Value;

    // Parse into UserScope object
    return new UserScope
    {
        Level = Enum.Parse<ScopeLevel>(scopeClaim),
        StationId = int.Parse(stationIdClaim),
        // ...
    };
}
```

### 2. Services

#### `Services/UserScopeService.cs`

**Purpose**: Determines user scope from roles and position.

**Key Methods**:
- `GetCurrentUserScope()`: Reads scope from claims
- `GetUserScopeAsync(int userId)`: Loads scope from database
- `DetermineScopeLevelAsync(int userId)`: Dynamic scope determination

**Scope Determination Flow**:
1. Load employee with active roles
2. Get `Role.ScopeLevel` from each role
3. Take **Min()** (broadest scope)
4. Fallback to HOD/Supervisor position if no roles
5. Default to Self

#### `Services/ScopeFilterService.cs`

**Purpose**: Applies scope filtering to queries.

**Key Method**:
```csharp
public IQueryable<T> ApplyScope<T>(IQueryable<T> query, UserScope? scope)
```

**How It Works**:
1. Checks if Organization scope → return all data
2. Checks entity type via `typeof(T)`
3. Routes to entity-specific filter method
4. Returns filtered query

**Currently Supported Entities**:
- `Employee`
- `Incident`
- `Hazard`

### Step 2: Apply Scope to Queries

**CRITICAL**: Always call `ApplyScope()` after building base query.

```csharp
public async Task<IActionResult> Index()
{
    // 1. Build base query with includes
    var query = _context.Employees
        .Where(e => e.EmploymentStatus == "Active")
        .Include(e => e.Station)
        .Include(e => e.Department);

    // 2. APPLY SCOPE - CRITICAL STEP!
    query = ApplyScope(query);

    // 3. Continue with filters, pagination, etc.
    if (!string.IsNullOrWhiteSpace(search))
    {
        query = query.Where(e => e.FirstName.Contains(search));
    }

    var employees = await query.ToListAsync();
    return View(employees);
}
```

### Step 3: Validate Single Record Access

For Edit/Details/Delete, verify the user can access that specific record:

```csharp
public async Task<IActionResult> Edit(int id)
{
    // Option 1: Use ApplyScope in the query
    var employee = await ApplyScope(_context.Employees)
        .FirstOrDefaultAsync(e => e.EmployeeId == id);

    if (employee == null)
    {
        return NotFound(); // Either doesn't exist or not in scope
    }

    // Option 2: Use CanAccessEmployeeAsync helper
    if (!await CanAccessEmployeeAsync(id))
    {
        return ForbidWithLog($"Attempted to edit employee {id}");
    }

    var employee = await _context.Employees.FindAsync(id);
    return View(employee);
}
```

## Adding Scope to New Models

When you create a **new entity** that needs scope protection, follow these steps:

### Step 1: Analyze Model Structure

Identify how the entity relates to organizational hierarchy:

**Option A: Direct Station Relationship**
```csharp
public class Training
{
    public int TrainingId { get; set; }
    public int StationId { get; set; }  // ← Direct relationship
    public string TrainingName { get; set; }
    // ...
}
```

**Option B: Via Employee Relationship**
```csharp
public class LeaveRequest
{
    public int LeaveRequestId { get; set; }
    public int EmployeeId { get; set; }  // ← Indirect via Employee
    public Employee Employee { get; set; }
    // ...
}
```

**Option C: Via User/Payroll Identifier**
```csharp
public class Inspection
{
    public int InspectionId { get; set; }
    public string ConductedByPayroll { get; set; }  // ← User identifier
    public int StationId { get; set; }
    // ...
}
```

### Step 2: Add Filter to ScopeFilterService

Open `Services/ScopeFilterService.cs` and add your entity:

#### 2a. Add to `ApplyScopeByType()` method:

```csharp
private IQueryable<T> ApplyScopeByType<T>(IQueryable<T> query, UserScope scope) where T : class
{
    var entityType = typeof(T);

    // Employee filtering
    if (entityType == typeof(Employee))
    {
        return (IQueryable<T>)ApplyEmployeeScope(query.Cast<Employee>(), scope);
    }

    // Incident filtering
    if (entityType == typeof(Incident))
    {
        return (IQueryable<T>)ApplyIncidentScope(query.Cast<Incident>(), scope);
    }

    // Hazard filtering
    if (entityType == typeof(Hazard))
    {
        return (IQueryable<T>)ApplyHazardScope(query.Cast<Hazard>(), scope);
    }

    // ✅ ADD YOUR NEW ENTITY HERE
    if (entityType == typeof(Training))
    {
        return (IQueryable<T>)ApplyTrainingScope(query.Cast<Training>(), scope);
    }

    // Default: no scope filtering (returns all)
    return query;
}
```

#### 2b. Add entity-specific filter method:

```csharp
/// <summary>
/// Filters Training records based on user scope
/// </summary>
private IQueryable<Training> ApplyTrainingScope(IQueryable<Training> query, UserScope scope)
{
    return scope.Level switch
    {
        // Organization sees everything
        ScopeLevel.Organization => query,

        // Station sees their station's trainings
        ScopeLevel.Station => query.Where(t => t.StationId == scope.StationId),

        // Department sees station-level trainings (customize if needed)
        ScopeLevel.Department => query.Where(t => t.StationId == scope.StationId),

        // Team sees trainings they conducted or attended
        ScopeLevel.Team => query.Where(t =>
            t.ConductedByPayroll == scope.PayrollNo ||
            t.Attendees.Any(a => a.PayrollNo == scope.PayrollNo)),

        // Self sees only trainings they attended or conducted
        ScopeLevel.Self => query.Where(t =>
            t.ConductedByPayroll == scope.PayrollNo ||
            t.Attendees.Any(a => a.PayrollNo == scope.PayrollNo)),

        // Default: no access
        _ => query.Where(_ => false)
    };
}
```

### Step 3: Create Controller Inheriting from ScopedController

```csharp
public class TrainingController : ScopedController
{
    public TrainingController(
        OshDbContext context,
        IScopeFilterService scopeFilter,
        ILogger<TrainingController> logger)
        : base(context, scopeFilter, logger)
    {
    }

    public async Task<IActionResult> Index()
    {
        // Build query
        var query = _context.Trainings
            .Include(t => t.Station);

        // ALWAYS apply scope
        query = ApplyScope(query);

        // Execute
        var trainings = await query.ToListAsync();
        return View(trainings);
    }

    public async Task<IActionResult> Details(int id)
    {
        // Apply scope to query
        var training = await ApplyScope(_context.Trainings)
            .Include(t => t.Station)
            .FirstOrDefaultAsync(t => t.TrainingId == id);

        if (training == null)
        {
            return NotFound(); // Either doesn't exist or not in scope
        }

        return View(training);
    }

    [HttpPost]
    public async Task<IActionResult> Create(TrainingViewModel model)
    {
        if (!ModelState.IsValid)
            return View(model);

        var training = new Training
        {
            TrainingName = model.TrainingName,
            ConductedByPayroll = CurrentPayrollNo,  // Use base property
            StationId = CurrentStationId ?? 0       // Use base property
        };

        _context.Trainings.Add(training);
        await _context.SaveChangesAsync();

        return RedirectToAction(nameof(Index));
    }
}
```

### Step 4: Add Extension Method (Optional)

Open `Extensions/ScopedQueryExtensions.cs` and add:

```csharp
/// <summary>
/// Filters Training records based on user scope
/// </summary>
public static IQueryable<Training> WithinScope(this IQueryable<Training> query, UserScope? scope)
{
    if (scope == null)
        return query.Where(_ => false);

    return scope.Level switch
    {
        ScopeLevel.Organization => query,
        ScopeLevel.Station => query.Where(t => t.StationId == scope.StationId),
        ScopeLevel.Department => query.Where(t => t.StationId == scope.StationId),
        ScopeLevel.Team => query.Where(t => t.ConductedByPayroll == scope.PayrollNo),
        ScopeLevel.Self => query.Where(t => t.ConductedByPayroll == scope.PayrollNo),
        _ => query.Where(_ => false)
    };
}
```

## Common Patterns

### Pattern 1: List View with Scope

```csharp
public async Task<IActionResult> Index(string search, int page = 1)
{
    const int pageSize = 15;

    // 1. Build base query
    var query = _context.Employees
        .Include(e => e.Station)
        .Include(e => e.Department)
        .AsQueryable();

    // 2. APPLY SCOPE FIRST (before any filters)
    query = ApplyScope(query);

    // 3. Apply search/filters
    if (!string.IsNullOrWhiteSpace(search))
    {
        query = query.Where(e =>
            e.FirstName.Contains(search) ||
            e.LastName.Contains(search));
    }

    // 4. Get total for pagination
    var total = await query.CountAsync();

    // 5. Apply pagination
    var items = await query
        .OrderBy(e => e.LastName)
        .Skip((page - 1) * pageSize)
        .Take(pageSize)
        .ToListAsync();

    ViewBag.TotalPages = (int)Math.Ceiling(total / (double)pageSize);
    return View(items);
}
```

### Pattern 2: Details/Edit with Access Check

```csharp
public async Task<IActionResult> Edit(int id)
{
    // Apply scope in the query - returns null if not in scope
    var employee = await ApplyScope(_context.Employees)
        .Include(e => e.Station)
        .Include(e => e.EmployeeRoles)
        .FirstOrDefaultAsync(e => e.EmployeeId == id);

    if (employee == null)
    {
        _logger.LogWarning($"User {CurrentUserId} attempted to access employee {id}");
        return NotFound(); // Don't reveal if record exists
    }

    return View(employee);
}
```

### Pattern 4: Dropdown Filtering by Scope

```csharp
private async Task PopulateDropdowns()
{
    // Employees dropdown - SCOPED
    var employees = await ApplyScope(_context.Employees)
        .Where(e => e.EmploymentStatus == "Active")
        .OrderBy(e => e.LastName)
        .Select(e => new {
            e.EmployeeId,
            FullName = e.FirstName + " " + e.LastName
        })
        .ToListAsync();

    ViewBag.Employees = new SelectList(employees, "EmployeeId", "FullName");

    // Stations - limit based on scope
    if (CanSeeAllData)
    {
        // Organization scope sees all stations
        ViewBag.Stations = await _context.Stations.ToListAsync();
    }
    else if (CurrentStationId.HasValue)
    {
        // Others see only their station
        ViewBag.Stations = await _context.Stations
            .Where(s => s.StationId == CurrentStationId.Value)
            .ToListAsync();
    }
}
```

## Testing and Troubleshooting

### Manual Testing Checklist

Test with different user roles to verify scope filtering:

**1. Organization Scope (Admin)**
- [ ] Can see all employees across all stations
- [ ] Can edit any employee
- [ ] Can see all incidents and hazards
- [ ] Dropdowns show all stations/departments

**2. Station Scope (Station Manager)**
- [ ] Can see only employees in their station
- [ ] Cannot see employees from other stations
- [ ] Can see station-level incidents/hazards
- [ ] Dropdowns limited to their station

**3. Department Scope (HOD)**
- [ ] Can see only employees in their department
- [ ] Cannot see other departments
- [ ] Can see station-level incidents

**4. Team Scope (Supervisor)**
- [ ] Can see only direct reports
- [ ] Cannot see other teams
- [ ] Can see incidents they reported

**5. Self Scope (Employee)**
- [ ] Can see only their own record
- [ ] Cannot see other employees
- [ ] Can see incidents they reported or were affected by

### Common Issues

#### Issue 1: "User sees data they shouldn't"

**Diagnosis**: `ApplyScope()` not called

**Fix**:
```csharp
// ❌ WRONG
var employees = await _context.Employees.ToListAsync();

// ✅ CORRECT
var employees = await ApplyScope(_context.Employees).ToListAsync();
```

#### Issue 2: "Scope not updating after role change"

**Diagnosis**: Scope is cached in authentication cookie

**Fix**: User must **log out and log back in** to refresh scope claims

#### Issue 3: "Query returns no results for all users"

**Diagnosis**: Scope filtering too restrictive or entity not added to ScopeFilterService

**Fix**: Add entity filtering to `ScopeFilterService.ApplyScopeByType()`

## Summary

The **dynamic scope-based authorization system** provides automatic, database-driven protection:

- ✅ **Dynamic**: Scope determined from `Role.ScopeLevel` in database
- ✅ **Extensible**: New roles can be added via database insert
- ✅ **Automatic**: Inherit from `ScopedController` and call `ApplyScope()`
- ✅ **Secure**: Users only see data within their authorized scope
- ✅ **Flexible**: Multiple roles supported - broadest scope wins
- ✅ **Fallback**: Position-based scope (HOD/Supervisor) if no roles

For implementation details, see:
- `Services/UserScopeService.cs` - Scope determination logic
- `Services/ScopeFilterService.cs` - Query filtering logic
- `Controllers/ScopedController.cs` - Base controller with helpers
- `Controllers/EmployeeController.cs` - Example implementation
